# infra/grafana

Провижининг Grafana: источник данных и дашборды подключаются файлами, а не руками в UI.

```text
grafana/
├── provisioning/
│   ├── datasources/prometheus.yml   # источник с фиксированным uid: prometheus
│   └── dashboards/dashboards.yml    # провайдер, читает каталог ниже
└── dashboards/
    └── auth-load.json               # «Auth — нагрузка и точки отказа»
```

Оба каталога монтируются в контейнер в [`deploy/docker-compose.yml`](../../deploy/docker-compose.yml). После `docker compose up -d grafana` дашборд доступен сразу, без настройки; `docker compose down` ничего не теряет.

## Почему uid у источника фиксированный

Панели ссылаются на источник по `uid: prometheus`. Если его поменять в `datasources/prometheus.yml`, все панели перестанут находить данные и покажут пустые графики без внятной ошибки.

## Дашборд auth-load

Четыре ряда, которые читаются сверху вниз:

| Ряд | Вопрос, на который отвечает |
|---|---|
| Методы (RED) | Сколько запросов, какая доля ошибок, какая задержка — по каждому методу |
| Защита bcrypt | Работает ли семафор: заняты ли все слоты, сколько ждут слот, сколько логинов пропущено и сколько отказано |
| Ресурсы | Почему упёрлось: пул соединений, CPU, горутины, память |
| k6 | Совпадает ли заданная нагрузка с фактической пропускной способностью |

Переменная `job` переключает профиль: `auth-local` — сервис запущен бинарём на хосте (соло-прогоны из [`shop-auth/load`](../../../shop-auth/load/README.md)), `auth-service` — контейнер в compose. В соло-режиме цель `auth-service` будет `down`, и наоборот — это ожидаемо.

Главный сигнал по базе — `go_sql_wait_count_total`: это запросы, которым не досталось соединения из пула. Пока он ноль, ограничение не в Postgres.

## Правки дашборда

`allowUiUpdates` выключен сознательно: иначе правки, сделанные в UI, живут только до рестарта контейнера и теряются молча. Порядок работы такой — поменять в UI, затем **Share → Export → Save to file** и положить JSON обратно в `dashboards/`.

## Известные проблемы

* **Имена метрик k6 зависят от версии.** Панели в ряду k6 рассчитаны на `k6_iterations_total`, `k6_dropped_iterations_total` и `k6_vus`. Если ряд пустой, посмотри фактические имена запросом `{__name__=~"k6_.+"}` в Prometheus и поправь выражения.
* **Дашборд только под auth.** Для catalog, cart, gateway и proxy аналогов нет, хотя метрики они отдают.
* **Нет алертов.** Пороги из плана (доступность Login и Refresh, p99, доля 5xx) нигде не заданы — пока это инструмент для прогонов, а не для дежурства.
